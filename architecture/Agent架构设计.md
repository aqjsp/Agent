> 作者：Q | 预计 20 篇 | 只讲架构决策，不讲基础教程

## 系列定位

这个系列不讲基础。Agent 是什么、Model 怎么调、Tool 怎么定义、Memory 三层架构、ReAct 循环——这些在之前的 7 章里已经讲过了。

这个系列只回答一个问题：**Agent 系统的架构怎么设计？**

架构设计不是"怎么写代码"，是"怎么在互相冲突的约束之间做取舍"。每篇文章聚焦一个架构决策，给出选择依据，不给出标准答案。

## 详细篇目

### 阶段一：状态与流程

#### 【Agent架构设计】第 1 篇：Agent 的 State 设计，是最容易被忽视的架构灾难

- **架构决策**：State 用 TypedDict 还是 Pydantic？Reducer 怎么选？状态膨胀怎么控制？
- **核心内容**：
  - State 不是"全局变量"——它是图的共享数据协议，定义了节点间能交换什么、怎么合并
  - Reducer 三种模式的取舍：覆盖（简单但危险）、追加（消息类场景）、累加（计数类场景）
  - 没有 Reducer 的并发写入 = 静默丢数据，LangGraph 直接抛异常的设计哲学
  - 状态膨胀：summary 字段、滑动窗口、跨子图隔离——不同策略的成本和风险
  - 不可变快照：为什么 State 版本化是 Time Travel 和 Fork 的前提
- **关键论点**：State 设计决定了 Agent 系统是"能跑"还是"能改"

#### 【Agent架构设计】第 2 篇：给 Agent 加个人工审批？没那么简单——HITL 的三种架构模式

- **架构决策**：人工介入是同步还是异步？介入后怎么恢复？
- **核心内容**：
  - 三种介入模式的架构差异：审批（approve/reject）、纠错（edit state）、引导（inject context）
  - interrupt 机制底层：Checkpoint + GraphInterrupt，不是"暂停线程"
  - 同步审批 vs 异步审批的生产架构：消息队列 + 通知 + 超时回退
  - 从 Checkpoint 分叉：审批不是二选一，可以并行探索多条路径
  - HITL 的成本：每次中断都是一次 LLM 上下文切换
- **关键论点**：HITL 的本质是"把人当作一种特殊的 Node"，不是"加个按钮"

#### 【Agent架构设计】第 3 篇：上下文工程——2026 年 Agent 最核心的技能

- **架构决策**：Agent 的上下文窗口里放什么、不放什么、什么时候放？
- **核心内容**：
  - Context Engineering ≠ Prompt Engineering：后者是写指令，前者是设计信息架构
  - 上下文窗口的四个竞争者：系统指令、对话历史、工具输出、检索结果
  - 渐进式披露（Progressive Disclosure）：按需加载，不是一次性全塞进去
  - 上下文预算管理：token 不是无限的，怎么分配给不同信息源
  - 上下文压缩策略：摘要、截断、选择性遗忘——每种策略的精度损失
- **关键论点**：Agent 的智商不取决于模型，取决于你喂给它什么上下文

#### 【Agent架构设计】第 4 篇：Agent 要跑 2 小时——长时运行任务的架构设计

- **架构决策**：Agent 运行时间从秒级到小时级，架构要做什么改变？
- **核心内容**：
  - 短时 Agent vs 长时 Agent：本质区别是"进程可能在任何一步挂掉"
  - Checkpoint 的频率权衡：每步存（安全但贵）vs 关键步存（省但恢复粒度粗）
  - 进程恢复的三个层级：自动恢复（K8s Job）vs 人工恢复（thread_id）vs 降级恢复（跳过失败步）
  - 长时 Agent 的上下文漂移：跑了几十轮后，LLM 的注意力已经不在最初的目标上了
  - 分段执行：把长任务拆成多个短时子图，每个子图独立 checkpoint
- **关键论点**：长时 Agent 不是"跑得更久的短时 Agent"，是不同的架构物种

### 阶段二：可靠性

#### 【Agent架构设计】第 5 篇：两个 Agent 同时改一条数据，谁覆盖谁——多 Agent 一致性设计

- **架构决策**：多 Agent 系统用强一致还是最终一致？
- **核心内容**：
  - 分布式一致性的经典问题在 Agent 中的特殊表现：LLM 输出不可重放
  - LangGraph 的 Reducer 机制已经是一种一致性保证——但只限于图内
  - 图间一致性：两个独立 StateGraph 操作同一资源时的冲突
  - 乐观锁 vs 悲观锁在 Agent 中的取舍
  - 幂等性设计：让 Agent 操作可以安全重试的架构模式
- **关键论点**：Agent 的一致性比传统分布式系统更难，因为 LLM 输出不确定，你不能靠重放来解决

#### 【Agent架构设计】第 6 篇：一个 Agent 挂了，整个系统跟着挂——级联故障怎么防

- **架构决策**：故障隔离的粒度是多粗？
- **核心内容**：
  - 五种典型故障模式：Agent 崩溃、通信超时、任务死锁、级联失败、状态污染
  - Circuit Breaker 模式在 Agent 中的应用：连续 N 次失败后自动熔断
  - 降级策略：单个 Agent 失败后的 plan B——跳过、替换、人工接管
  - 超时设计：不是所有任务都值得等，怎么设超时阈值
  - 状态污染的隔离：一个 Agent 的错误输出不要传播到其他 Agent
- **关键论点**：Agent 系统的可靠性目标不是"不出错"，是"出错后系统还能降级运行"

#### 【Agent架构设计】第 7 篇：Agent 怎么测？非确定性系统的评估架构

- **架构决策**：怎么评估一个输出每次都不一样的系统？
- **核心内容**：
  - 确定性测试对 Agent 失效——同一个输入，两次输出可能完全不同
  - 三层评估：组件级（工具/模型）、图级（流程正确性）、端到端（目标达成率）
  - LLM-as-Judge：用另一个 LLM 评估 Agent 输出的质量——可行但有偏
  - 回归测试的新范式：不是 assert 输出值，而是 assert 执行路径和状态变化
  - 评估数据集的构建：怎么标注"好"和"不好"的 Agent 轨迹
- **关键论点**：Agent 的测试架构比 Agent 本身更难设计

#### 【Agent架构设计】第 8 篇：一句话让你的 Agent 删库跑路——Agent 安全架构

- **架构决策**：安全边界划在哪个层级——模型层、工具层、还是编排层？
- **核心内容**：
  - Prompt Injection 的三类攻击面：用户输入、工具返回、检索内容
  - 工具权限模型：每个 Agent 只能访问它需要的工具——最小权限原则
  - 沙箱执行：代码执行 Agent 必须在隔离环境中运行
  - Guardrails 的架构位置：输入护栏 vs 输出护栏 vs 工具护栏
  - 安全的代价：每多一层防护，Agent 的自由度就少一分
- **关键论点**：Agent 安全是架构问题，不是模型能力问题——再强的模型也会被注入

### 阶段三：多 Agent 深水区

#### 【Agent架构设计】第 9 篇：Supervisor vs Swarm——两种多 Agent 架构的灵魂差异

- **架构决策**：多 Agent 系统用中心调度还是自主交接？
- **核心内容**：
  - Supervisor 模式：控制精确、调试容易，但单点瓶颈
  - Swarm 模式：弹性好、无单点，但执行路径不可预测
  - 混合架构：Supervisor 做"门面"，内部用 Swarm 自主协作
  - 选择矩阵：按任务耦合度、Agent 自治度、调试需求三维度选择
  - Anthropic 多 Agent 研究系统的架构案例分析
- **关键论点**：Supervisor 和 Swarm 不是"谁更好"，是"控制 vs 弹性"的架构取舍

#### 【Agent架构设计】第 10 篇：多个 Agent 共享一个全局变量，迟早要出事——通信架构设计

- **架构决策**：Agent 间通信用共享状态还是消息传递？
- **核心内容**：
  - 共享状态的问题：隐式耦合、竞态条件、调试困难
  - 消息传递的问题：上下文丢失、消息膨胀、延迟
  - LangGraph 子图的状态隔离：parent/child state 映射的工程细节
  - 混合架构：控制面用共享状态，数据面用消息传递
  - Agent 间上下文传递的精度损失：每次传递都会丢失信息
- **关键论点**：通信架构决定了系统是"可控但死板"还是"灵活但混乱"

#### 【Agent架构设计】第 11 篇：Agent 的权限模型——不是每个 Agent 都该有删库权限

- **架构决策**：怎么给 Agent 分配最小必要权限？
- **核心内容**：
  - Agent 权限的三个维度：可访问的工具、可修改的数据、可触发的操作
  - 基于角色的权限模型：Reader、Writer、Admin——不同 Agent 不同角色
  - 工具级权限控制：同一个数据库，Agent A 只能读，Agent B 能写
  - 权限与任务的关系：权限应该跟着任务走，不是跟着 Agent 走
  - 权限提升的审批流程：Agent 需要更高权限时怎么办
- **关键论点**：最小权限原则在 Agent 中比传统系统更重要——因为 Agent 的行为不可预测

#### 【Agent架构设计】第 12 篇：LangGraph、CrewAI、AutoGen、Temporal——编排架构的底层差异

- **架构决策**：不同编排框架的执行模型差异，决定了什么场景适合什么框架
- **核心内容**：
  - 执行模型对比：StateGraph（BSP）vs 线性任务链 vs 对话式协商 vs DAG 重放
  - LangGraph：循环+持久化，但 API 重、学习曲线陡
  - CrewAI：上手快，但控制精度低，没有真正的循环
  - AutoGen：弹性最高，但执行不可预测
  - Temporal/Prefect：DAG 假设确定性重放，对 LLM 不成立
  - 选型决策树：不是"谁更好"，是"执行模型是否匹配任务特征"
- **关键论点**：编排框架的选择取决于任务的运行特征，不是功能列表

### 阶段四：生产

#### 【Agent架构设计】第 13 篇：Agent 上了生产就是黑盒？3 层观测让你不再盲飞

- **架构决策**：观测的粒度和成本怎么平衡？
- **核心内容**：
  - Agent 为什么比传统服务更难调试：非确定性 + 长链路 + 多步骤
  - 三层观测：Trace（执行轨迹）、Span（节点耗时）、State Diff（状态变化）
  - LangSmith 的 trace 模型 vs 自定义 OpenTelemetry 方案
  - Time Travel 调试：从 Checkpoint 回到任意点重放
  - 采样策略：不是每个请求都全量 trace——成本和覆盖率的取舍
- **关键论点**：没有可观测性的 Agent 系统，上了生产就是盲飞

#### 【Agent架构设计】第 14 篇：Agent 跑一个月，Token 账单 5 万——成本架构怎么设计

- **架构决策**：怎么在不牺牲质量的前提下控制 Agent 成本？
- **核心内容**：
  - Agent 成本的三驾马车：LLM Token、Checkpoint 存储、观测开销
  - 降低推理成本的三条路径：模型分层（小模型做简单事）、缓存（相同输入不重复调）、规划优化（尽早收敛）
  - 降低工具成本：结果缓存、批处理、提前终止
  - Checkpoint 的 Delta Channel：只存增量，不存全量
  - 成本预算机制：token 上限 + 超限自动降级 + 用量告警
- **关键论点**：不控制成本的 Agent 系统，要么被关掉，要么被限流

#### 【Agent架构设计】第 15 篇：Agent 部署不是加个 Docker——有状态服务的部署难题

- **架构决策**：Agent 部署架构和传统无状态服务的本质区别
- **核心内容**：
  - Agent 是有状态服务：同一个 thread_id 的后续请求必须路由到同一实例（或者用共享 Checkpoint）
  - 单机架构：SqliteSaver + FastAPI + Docker——够用但不水平扩展
  - 分布式架构：PostgresSaver + K8s + 消息队列——扩展但复杂
  - LangGraph Platform：托管方案，但锁定了技术栈
  - 灰度发布的特殊挑战：两个版本的 Agent 可能对同一 State 有不同理解
- **关键论点**：Agent 部署的核心难题是"有状态 + 长连接 + 非确定性"，传统部署经验不适用

#### 【Agent架构设计】第 16 篇：Agent 在沙箱里运行——隔离架构的工程实现

- **架构决策**：Agent 的执行环境怎么隔离？隔离到什么粒度？
- **核心内容**：
  - 为什么 Agent 需要沙箱：代码执行、文件操作、网络请求——每个都可能是攻击面
  - 沙箱的三种架构：进程级（subprocess）、容器级（Docker）、VM 级（Firecracker）
  - 工具级沙箱：不同工具有不同的隔离需求——搜索不需要沙箱，代码执行必须沙箱
  - 沙箱与 Checkpoint 的交互：沙箱状态不属于 State，崩溃后怎么恢复
  - 沙箱的性能代价：隔离越强，延迟越高
- **关键论点**：沙箱不是可选项，是代码执行 Agent 的硬性要求

### 阶段五：协议与演进

#### 【Agent架构设计】第 17 篇：MCP——让 Agent 的工具从"各自为政"到"统一标准"

- **架构决策**：MCP 会改变 Agent 工具系统的架构吗？
- **核心内容**：
  - MCP 解决的根本问题：工具定义的碎片化——每个框架有自己的工具格式
  - MCP 的三层架构：Host（Agent 进程）→ Client（协议客户端）→ Server（工具服务）
  - MCP 与传统 API 集成的区别：描述即接口——LLM 读描述选工具
  - MCP Server 的开发模式：一个 Server 暴露一组工具，独立部署
  - MCP 在 LangGraph 中的集成：工具不再是代码级依赖，而是服务级依赖
- **关键论点**：MCP 让工具从"编译时依赖"变成"运行时发现"——这是架构范式的变化

#### 【Agent架构设计】第 18 篇：A2A——不同框架的 Agent 终于能对话了

- **架构决策**：Agent 间通信需要标准化协议吗？
- **核心内容**：
  - A2A 解决的问题：不同框架（LangGraph、CrewAI、AutoGen）的 Agent 无法互操作
  - A2A 与 MCP 的分工：MCP 管 Agent 用什么工具，A2A 管 Agent 之间怎么协作
  - A2A 的通信模型：Agent Card（能力声明）→ Task（任务委派）→ Message（状态同步）
  - A2A 的成熟度：2026 年初发布，仍在快速迭代
  - 企业内多 Agent 生态的架构：A2A 作为内部 Agent 通信的标准协议
- **关键论点**：A2A 是 Agent 从"单体应用"走向"生态网络"的协议基础

#### 【Agent架构设计】第 19 篇：Agent 怎么自己变强？又怎么防止它"学歪"

- **架构决策**：Agent 的自我改进机制怎么设计，边界在哪？
- **核心内容**：
  - 三种自进化模式：技能积累（学会用新工具）、策略优化（改进决策）、架构演进（自动调图拓扑）
  - Reflexion 的自我反思循环：失败 → 分析原因 → 修改策略 → 重试
  - AgentFactory 的技能工厂：Agent 自动生成新工具并注册
  - 基于评估反馈的自动 prompt 优化：eval → 分析 → 修改 system prompt → 再 eval
  - 自进化的安全边界：怎么防止 Agent 学到"捷径"（如跳过审批步骤）
- **关键论点**：自进化 Agent 是方向，但必须有人类监督的"熔断机制"

#### 【Agent架构设计】第 20 篇：Agent 的未来不是一个超级大脑，是一群专业工人的网络

- **架构决策**：Agent 系统的架构终态是什么形态？
- **核心内容**：
  - Computer Use Agent：Agent 直接操作 UI，不再依赖 API——但可靠性挑战巨大
  - SLM Micro-Agent：小模型做专门任务（工具调用、格式转换），大模型做复杂推理——分层架构
  - 元认知架构：Agent 的"思维调控器"——自我评估置信度、动态选择策略、熔断机制
  - Agent 生态系统：从单体 Agent → 团队协作 → 跨组织网络——架构的三个阶段
  - 最终形态猜想：Agent 不是"一个超级大脑"，是"一群专业工人组成的网络"
- **关键论点**：Agent 的未来不是把一个模型做得更强，是把很多小 Agent 连得更紧密

## 写作原则

1. **只讲架构决策**。不重复基础教程内容。每篇回答一个"怎么取舍"的问题。
2. **先说约束，再说方案**。架构是约束下的取舍，没有约束就没有架构问题。
3. **给选择依据，不给标准答案**。"取决于 X"比"应该选 Y"更有价值。
4. **代码只为说明架构**。不写完整项目，只写体现架构决策的关键片段。
5. **每篇配架构图**。SVG 格式，不靠文字描述拓扑。
